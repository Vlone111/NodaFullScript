# rw-edge installer

Ставит 443-only edge на чистый Debian/Ubuntu: HAProxy спереди, Caddy с настоящим
сайтом прикрытия, pinned-нода Remnawave с Xray за ними, и любая комбинация
поддерживаемых транспортов.

С панелью не разговаривает. Генерирует точные значения и печатает пошаговую
инструкцию, что вставить руками.

## Запуск

```sh
scp rw-edge-install.sh root@новый-сервер:/root/
ssh root@новый-сервер
chmod 700 rw-edge-install.sh
./rw-edge-install.sh
```

Команды: `install` (по умолчанию), `verify`, `steps`, `rollback`.
Переменная `RW_ENABLE_UFW=1` включает firewall без интерактивного подтверждения.

## Что спрашивает

1. IP панели, порт Node API, `SECRET_KEY` ноды (ввод скрыт, проверяется на
   разбор base64 и наличие `nodeCertPem`).
2. Какие транспорты поднять — можно несколько номеров через пробел.
3. Домены: ровно столько, сколько нужно выбранным вариантам. A-записи ставите
   сами заранее, скрипт проверяет их через два независимых резолвера и ругается
   на лишние AAAA.
4. Git URL и **тег** репозитория с сайтом прикрытия.

## Транспорты

| id | Домен | Сертификат | Кто терминирует TLS |
|---|---:|---:|---|
| `reality-tcp-steal` | 1 | да | Xray, fallback в Caddy |
| `reality-tcp-borrow` | 0 | нет | Xray, target — внешний донор |
| `reality-xhttp-steal` | 1 | да | Xray, fallback в Caddy |
| `xhttp-tls` | 1 | да | Caddy, дальше h2c |
| `grpc-tls` | 1 | да | Caddy, дальше h2c |
| `tcp-tls` | 1 | да | Xray, сертификат смонтирован |
| `hysteria2` | 1 | да | Xray на UDP/443, masquerade на сайт |

`reality-tcp-steal` и `reality-tcp-borrow` вместе запрещены и отклоняются на
этапе вопросов: оба претендуют на один RAW-инбаунд и один `default_backend`.

Полный контракт архитектуры — в [`../DESIGN.md`](../DESIGN.md).

## Сайт прикрытия

Скрипт клонирует репозиторий сайта по тегу и, если в нём есть
`tools/make-assets.sh`, разово генерирует медиа через ffmpeg. Это единственный
шаг, который нагружает CPU, и он выполняется один раз при установке; ffmpeg
ставится только если его нет.

Повторный запуск установщика переиспользует уже сгенерированное медиа и заново
кодировать не будет.

В покое отдача сайта стоит почти ничего: замерено 11 МБ RAM и 0% CPU у Caddy
под 30 одновременными загрузками.

Caddy настраивается под медиа отдельно: корректные MIME для `.m3u8`, `.m4s` и
`.mpd`, сжатие только для текста, годовой immutable-кэш для `/media/**` и
короткий для `SHA256SUMS`. Range-запросы работают нативно.

## Что делает с системой

- `sysctl`: BBR поверх fq, увеличенные accept-очереди и **UDP-буферы 16 МБ**
  (без них QUIC и Hysteria2 упираются в потолок задолго до полосы канала);
- лимиты файловых дескрипторов;
- Docker из официального репозитория, если его нет;
- UFW: default-deny, SSH на фактическом порту, `443/tcp`, `443/udp` только при
  выбранном Hysteria2, Node API — только с IP панели;
- cron-хук синхронизации сертификатов, если выбраны `tcp-tls` или `hysteria2`.

Всё обратимо: `rollback` останавливает контейнеры и снимает cron, файлы и тома
не трогает намеренно.

## Валидация

Ни один конфиг не доезжает до системы, не пройдя проверку настоящими
бинарями из тех же digest-pinned образов:

```sh
./test-matrix.sh
```

Рендерит все поддерживаемые комбинации и гоняет каждую через
`xray run -test`, `haproxy -c` и `caddy validate`, плюс отдельно проверяет, что
несовместимая пара действительно отклоняется. Систему не трогает.

## Сборка

Скрипт собирается из `parts/*.sh`:

```sh
./build.sh
```

Правьте части, не собранный файл.

## Известные ограничения

- **Masquerade Hysteria2 здесь не проверяется автоматически.** Схема сверена с
  документацией Xray и валидируется ядром, но `xray run -test` молча глотает
  неизвестные поля, поэтому доказать работу masquerade может только настоящий
  HTTP/3-запрос. Скрипт об этом честно предупреждает; проверяйте вручную
  `curl --http3 https://<домен>/` с машины, где curl собран с HTTP/3.
- **UDP/443 держит один процесс.** При выбранном Hysteria2 Caddy не отдаёт
  HTTP/3 сам, и `Alt-Svc` не анонсируется — иначе сайт обещал бы H3, которого
  на его собственном порту нет.
- **Сертификаты для `tcp-tls` и `hysteria2`** копируются из тома Caddy по его
  внутренней раскладке. Раскладка стабильна много лет, но это зависимость от
  чужой детали реализации; при мажорном обновлении Caddy проверьте
  `sync-certs.sh`.
